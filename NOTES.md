## 0.1 — окружение

- `uv init --package <name>` создаёт **новую** директорию; внутри существующей — без имени.
- venv не переносят и не коммитят: внутри абсолютные пути (shebang, `pyvenv.cfg`). Сломался → `rm -rf .venv && uv sync`.
- Команды запускаются через `uv run ...`, активировать venv не нужно.
- `uv.lock` коммитим — окружение воспроизводится один в один.

## 0.2 — Pydantic и модели домена

### Pydantic vs dataclass vs mypy
- dataclass — просто контейнер, типы в рантайме не проверяются: `Deploy(started_at="вчера")` создастся.
- Pydantic проверяет и преобразует данные **в рантайме**: `"2026-09-22T14:00:00Z"` → `datetime`, мусор → `ValidationError` с путём к полю.
- mypy проверяет **код до запуска**, данные из JSON он видеть не может. `""` для него — нормальный `str`.
- Правило: Pydantic на границах (API, файлы, ответы LLM, tools, checkpoints, env), внутри — dataclass.
- `model_json_schema()` — именно эту схему получает LLM для structured output и описания tools.

### Синтаксис полей
- `name: str = Field(min_length=1)` — после `:` тип, после `=` значение/настройки. `Field(...)` — вызов функции, не тип.
- `Annotated[str, Field(min_length=1)]` — тип + метаданные. Python и mypy видят только `str`, Pydantic читает метаданные.
- `NonEmptyStr = Annotated[...]` — псевдоним, чтобы не повторять ограничение в каждом поле.

### Базовая модель
- `DomainModel` — настройки один раз, все модели наследуют.
- `frozen=True` — поля нельзя переприсвоить. Но список внутри всё равно можно изменить (`.append`) → для коллекций берём `tuple[X, ...]` (`...` = любая длина).
- `extra="forbid"` — лишнее поле в данных = ошибка. Пример из практики: забыл `change_summary` в `Deploy` → загрузка упала бы, а без `forbid` поле молча потерялось бы.

### Enum или str
- Тест: есть ли в коде ветки по конкретным значениям? Да → enum (`DeployStatus`, `LogLevel`). Нет, значения можно заменить любыми → `str` (имена сервисов, команды).
- Не уверен → начинай с `str`: превратить в enum позже проще, чем выпиливать.
- Enum описывает предметную область, а не текущие фикстуры → `IN_PROGRESS`, `FAILED`, `DEBUG`, `CRITICAL` нужны, даже если их нет в данных.
- `StrEnum` — значения одновременно строки; Pydantic сам превращает `"degraded"` в `DependencyStatus.DEGRADED` и отклоняет неизвестное.
- Ловушка: `StrEnum` сравнивается по алфавиту — `LogLevel.ERROR < LogLevel.WARNING` по строкам, а не по важности. Для порядка важности нужен явный порядок.

### == и is
- `==` — равны ли значения, `is` — тот же ли объект.
- Члены enum — синглтоны → сравнивать через `is`. С `StrEnum` `==` пропустит и обычную строку: `MetricName.ERROR_RATE == "error_rate"` → `True`.
- `is` только для `None`, членов enum, `True`/`False`. Строки и числа через `is` не сравнивать.

### Числа и валидаторы
- `float`, а не `float | int`: для mypy `int` и так подходит к `float`; Pydantic приведёт `320` → `320.0`, и дальше в коде один тип.
- `Field(ge=0, allow_inf_nan=False)` — по умолчанию Pydantic пропускает `NaN`/`inf`, а `NaN` тихо ломает сравнения.
- Правило зависит от другого поля (`error_rate ≤ 1`) → `Field` не подходит, он видит только своё поле → `@model_validator(mode="after")`.
- `mode="after"` — поля уже провалидированы: `self.metric` уже enum, `self.value` уже float. Обязательно `return self`.
- `ValueError` внутри валидатора Pydantic сам превращает в `ValidationError`.

### Loaders
- Что делает: загружает 5 файлов → `FixtureDataset` → проверяет, что все ссылки на сервисы и зависимости существуют (`depends_on`, деплои, метрики, логи).
- `FixtureDataset` — dataclass с именованными полями вместо кортежа из 5 элементов или словаря: mypy знает, что `dataset.deploys` — это `tuple[Deploy, ...]`, порядок не перепутать, опечатку в имени поля ловит mypy. Dataclass, а не Pydantic — внутри уже провалидированные модели.
- После загрузки это не сырой JSON: `deployed_at` — `datetime` с UTC, `status` — член enum.
- Своё исключение + общий базовый класс `FixtureError` → вызывающий ловит одно `except`, новые подклассы его не ломают.
- `raise ... from exc` — сохраняет исходную ошибку как причину.
- Модель угроз: от кого защищаемся? Здесь — от своей опечатки при правке фикстур. Проверки только там, где опечатка иначе молча сломает агента.
- Идти итерациями: контракт → один файл → простые ошибки → тест → усложнять, когда появится причина.

### Коллекции и comprehensions
- `{x.name for x in items}` — set comprehension (множество). С двоеточием `{k: v for ...}` — словарь. Пустые `{}` — это словарь, пустое множество — `set()`.
- `a | b` для множеств — объединение. Для типов (`int | None`) тот же символ значит «или тот, или другой тип».
- `in` по множеству мгновенный, по списку — перебор всех элементов. Для проверок «есть ли такое имя» — множество.
- `set(...)` убирает дубли, `sorted(...)` фиксирует порядок (стабильные сообщения и тесты).
- Несколько `for` в comprehension = вложенные циклы, порядок слева направо = порядок вложенности; выражение пишется первым, `if` последним. Предел читаемости: два `for` и один `if`, дальше обычные циклы.
- `.extend(iterable)` добавляет все элементы в конец списка, меняет его на месте. `.append(x)` добавляет `x` одним элементом: `[1, 2].append([3, 4])` → `[1, 2, [3, 4]]`.
- `.extend` и `.append` возвращают `None` → `items = items.extend(...)` теряет список. `extend("ab")` добавит `"a"` и `"b"` по отдельности.
- Пустой список под `mypy --strict` нужно аннотировать: `referenced: list[tuple[str, str]] = []`, иначе ошибка `Need type annotation`.

## Как работаем
- Итерациями: контракт → минимальная версия → простые ошибки → тест → усложнять, когда появится причина.
- Проверки оправдываются моделью угроз, а не «на всякий случай».
- Код, который попадёт в резюме, пишу сам; скучную подготовку делает Claude.
